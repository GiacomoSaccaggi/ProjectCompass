Frontend Architecture, Templates & HTMX 2.0

How ProjectCompass trims its Web UI canvas: the header.html partial-injection system, global PublicAppSettings context, HTMX 2.0 partial swaps, and the complete reference for all 40+ Jinja2 templates.

05 • Sailcloth & Canvas Jinja2 + HTMX 2.0 Zero-Build Assets

1. The header.html Partial Injection System

Rather than relying on deep Jinja2 {% extends %} chains, ProjectCompass uses a fast, deterministic partial-injection mechanism managed by HTMLUtils (`utils/html_utils.py`). At startup, templates/header.html is parsed via HTML comment markers into three reusable layout segments stored in self.html_parts: 

<!-- start head -->
  <!-- Global CSS, W3.CSS, HTMX 2.0, Chart.js, theme variables -->
<!-- end head -->

<!-- start top_container -->
  <!-- Top navigation bar, demo notice banner, user profile & theme controls -->
<!-- end top_container -->

<!-- start sidebar_menu -->
  <!-- Collapsible left navigation drawer respecting FeatureGate toggles -->
<!-- end sidebar_menu -->

Before rendering a view, route handlers call webapp.substitute_html(port=..., project_folder=...) and pass the resulting dictionary into render_template(...). Every full-page template includes them at the top of the document: 

{{ head|safe }}
{{ top_container|safe }}
{{ sidebar_menu|safe }}

2. Global Context Variables & pc Settings

In addition to the injected layout strings, app.py registers a Flask context processor (inject_pc_settings) that exposes pc (PublicAppSettings) to every template automatically.

Variable Type Description
head, top_container, sidebar_menu str (HTML) Rendered layout partials produced by webapp.substitute_html().
pc PublicAppSettings Validated presentation settings from projectcompass.yaml: pc.branding (app name, tagline, logo), pc.theme (accent color, font, dark mode), pc.features (module visibility booleans), pc.notice, and pc.footer.
title str Application title loaded from templates/environment_variables/title.txt or overridden by pc.branding.app_name.
links dict Sidebar external/useful links loaded from templates/environment_variables/links.yaml.
tool_choices dict Dropdown options for products, countries, and output types from tool_choices.yaml.

3.1 Workspace, Catalog & Pipelines

Template File Route(s) Purpose & Key Variables
landing.html & index.html GET / Main dashboard displaying KPI counters (number_of_analysis, number_of_owners, number_of_structured_analysis, number_of_products) and Chart.js polar/bar breakdowns.
overview.html GET /overview/ In-app platform overview and quick-navigation launchpad.
analysis.html GET /analysis/ Full catalog view with instant client-side + FTS5 filtering, favorites toggle, star ratings, comments modal, RAG index status badges, and ⚡ Flow badges with "Edit Code" buttons for analyses that have compass_flow.yaml + Dockerfile.
create_analysis.html GET /create_analysis/ Unified create/edit form (`new_analysis=True|False`) for uploading HTML, `.ipynb`, or `.py` structured analyses.
import.html GET /import/ Bulk archive/folder import interface for existing analyses and notebooks.
pipeline_builder.html & pipeline_versions.html GET /pipeline_builder/, GET /pipeline_versions/<name> Interactive visual studio for wiring scomp-link pipeline blocks, previewing generated Python code, and restoring versioned snapshots.
investigations.html GET /investigations/ Dynamic parameter input form generated from compass_flow.yaml to execute flows.
versions_single_analysis.html, outputs.html, iframetemplate.html GET /versions_single_analysis/, GET /outputs/, GET /iframetemplate/ Version manager for physical outputs and dashboard links, plus the iframe/HTML report viewer.
executions.html & schedules.html GET /executions/, GET /schedules/ Unified execution history console with SSE live log modal and APScheduler cron job manager.
