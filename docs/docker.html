Docker Compose, Mithril Sidecar & Production Deployment

How to berth ProjectCompass and the Mithril multi-model LLM engine with Docker Compose, configure persistent volumes (`DATA_DIR=/app/data`), run health checks, and harden production deployments.

11 • Drydock & Berth Docker Compose + Mithril Production Checklist

1. Container Services Architecture

ProjectCompass ships with multi-profile Docker Compose configurations pairing the Gunicorn-served Flask application with Mithril:

Service Name Container Image Host Port Internal Port Role
projectcompass_app ghcr.io/giacomosaccaggi/projectcompass:latest (or local Dockerfile) 8080 5000 ProjectCompass Master web UI, REST API, DuckDB/ConnectorX engine, and APScheduler leader.
mithril ghcr.io/giacomosaccaggi/mithril:latest 16180 16180 Multi-model LLM orchestration & cross-encoder reranking engine (Gemini, OpenAI, Anthropic, Groq, local GGUF).

2. Docker Compose Variants & Quick Start

Compose File Target Environment Launch Command
docker-compose.public.yml Zero-clone evaluation using pre-built GHCR images docker compose -f docker-compose.public.yml up -d
docker-compose.yml + docker-compose.override.yml Local development with live host bind mounts docker compose up -d
docker-compose.yml + docker-compose.prod.yml Production deployment with restart policies & resource caps docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d 
# 1. Start both ProjectCompass (:8080) and Mithril (:16180)
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d

# 2. Stream container logs
docker compose logs -f projectcompass_app

# 3. Verify health check endpoints
curl -fsSL http://localhost:8080/health
curl -fsSL http://localhost:8080/check

3. Persistent Volumes & State Layout

To ensure SQLite databases (`projectcompass.db`, `scheduler_jobs.db`), ChromaDB RAG embeddings (`rag_data/`), encrypted DB connection keys (`tmp/.db_connections.key`), and catalog analyses survive container upgrades, mount `/app/data` (or individual directories) persistently:

Host Path / Volume Container Path Persisted Artifacts
./data (or named volume) /app/data (DATA_DIR) projectcompass.db, scheduler_jobs.db, rag_data/, tmp/.db_connections.key, projectcompass.yaml
./Analyses /app/Analyses Catalog analysis folders, Structured Analyses, Pipeline configs, and k0s Flow scripts (`flow.py`)
./Saved_data & ./Saved_queries /app/Saved_data & /app/Saved_queries Uploaded CSV/SQLite datasets and saved `.sql` files
./logs /app/log Structured application and Gunicorn access/error logs
./.mithril /root/.mithril Mithril provider configuration and cached local model weights

4. Production Hardening Checklist

🛡️ Helm Control — Mandatory Pre-Flight Checklist
  • Set Fixed Cryptographic Keys: Always provide persistent SECRET_KEY and DB_CONNECTIONS_KEY in `.env` so sessions and encrypted ConnectorX database credentials remain valid across container recreations.
  • Configure Admin & Bearer Credentials: Set ADMIN_PASSWORD_HASH (generated via werkzeug.security.generate_password_hash) or complete the /setup wizard immediately on first boot.
  • Single Scheduler Leader: When scaling Gunicorn workers inside a single container, `acquire_scheduler_lock()` (`fcntl.flock` on `/app/data/tmp/scheduler.lock`) guarantees only one worker executes cron jobs. Do not run multiple independent container replicas against the same SQLite file.
  • Mount Kubeconfig for External k0s Master: If ProjectCompass runs in Docker and orchestrates a host or remote k0s cluster, mount the readable kubeconfig file into the container and set KUBECONFIG_PATH=/app/data/k0s-compass.conf.
