End-to-End User Guide (Skipper's Manual)

Practical, step-by-step seamanship for every workflow in ProjectCompass: cataloging analyses, writing executable Structured Analyses, rigging visual scomp-link ML pipelines, querying local/remote databases, and chatting with per-analysis RAG.

02 • Skipper's Manual Catalog & Pipelines SQL + RAWGraphs + RAG

1. First-Time Setup & Navigation

When you launch ProjectCompass (default http://localhost:5002 in local dev or http://localhost:5000 via Gunicorn/Docker), if no administrator account exists yet, the application automatically redirects to the Setup Wizard (/setup).

  1. Create the initial Admin user and configure optional workspace defaults.
  2. Once signed in, use the left sidebar (injected via header.html) to switch between:
    • Overview / Dashboard (/) — KPI counters, recent executions, and product distribution charts.
    • Analysis Catalog (/analysis/) — Search, filter, launch, rate, and manage all analyses.
    • Pipeline Builder (/pipeline_builder/) — Compose and run scomp-link pipelines.
    • Data Explorer (/query_results/ & /connections) — Run DuckDB or remote ConnectorX SQL queries.
    • AI Chat (/chat) — Ask natural-language questions over datasets or per-analysis RAG indexes.
    • Kubernetes Console (/workers, /flows, /chains, /runs) — Operate distributed k0s jobs.

2. Creating & Managing Catalog Analyses

ProjectCompass stores every analysis inside its own subdirectory under Analyses/<Analysis Name>/, synchronized with the SQLite AnalysisRecord table and analyses_fts full-text index. Navigate to Create Analysis (/create_analysis/?new_analysis=True) or Import (/import/) to register work in one of four modes:

Analysis Mode Required Files How ProjectCompass Renders & Executes It
Static HTML / Report Any .html report or external dashboard URL Served inside the iframe viewer (/iframetemplate/) with versioned history in output_versions.yaml.
Jupyter Notebook (.ipynb) .ipynb file uploaded via Create or Import Automatically converted to standalone HTML via nbconvert and indexed for code/markdown RAG search.
Structured Analysis structured_analysis_main.py + metadata_automatic_report.yaml Generates a dynamic parameter form at /investigations/, executes in a background thread (or k0s Pod), and streams logs via SSE.
Scomp-Link Pipeline pipeline_config.json + generated structured_analysis_main.py Created visually in /pipeline_builder/; supports versioned snapshots (PipelineVersion) and one-click execution.

Authoring a Structured Analysis

To make a Python analysis executable from the Web UI, API, or Scheduler, include two files inside its analysis/ subfolder:

  1. metadata_automatic_report.yaml — Declares the form inputs shown to users.
  2. structured_analysis_main.py — Defines a run(inputs: dict, output_path: str) function (or executes directly as a script).
# Analyses/Sales Performance Report/analysis/metadata_automatic_report.yaml
region:
  name: "Target Region"
  description: "Geographic region to filter sales records"
  type: "select"
  options: ["All", "North", "South", "East", "West"]
  default: "All"

min_amount:
  name: "Minimum Order Amount ($)"
  description: "Exclude transactions below this threshold"
  type: "number"
  default: 100
# Analyses/Sales Performance Report/analysis/structured_analysis_main.py
from pathlib import Path
import pandas as pd


def run(inputs: dict, output_path: str) -> str:
    """Execute parameterized analysis and write an HTML report to output_path."""
    region = inputs.get("region", "All")
    min_amount = float(inputs.get("min_amount", 100))

    print(f"[SalesReport] Filtering region={region}, min_amount={min_amount}")
    # Load data, compute KPIs, and write output HTML
    out_file = Path(output_path) / "report.html"
    out_file.write_text(f"<h1>Sales Report ({region})</h1><p>Threshold: ${min_amount}</p>", encoding="utf-8")
    return str(out_file)
⚓ Voyage Tip — Automatic Documentation & Dependency Extraction

When you upload `.py` files into an analysis, AnalysisUtils.upload_new_analysis() automatically extracts imported third-party packages into requirements.txt, pulls SQL queries from docstrings into sql_extractions/, and generates API documentation via pdoc.

3. Visual Pipeline Builder & Scomp-Link

Open Pipeline Builder (/pipeline_builder/) to construct end-to-end machine learning and data processing pipelines using scomp-link blocks. 

flowchart LR
  A["📥 DataLoaderBlock (CSV / SQL)"] --> B["🧹 Clean and Impute Block"]
  B --> C["⚙️ FeatureEngineeringBlock"]
  C --> D["🎯 ModelTrainerBlock (LightGBM / XGBoost / Sklearn)"]
  D --> E["📊 ScompLinkHTMLReport (KPIs, Plots and Drift)"]
Figure 1 — Visual Scomp-Link pipelines compile directly to composable Python `>>` expressions and versioned `PipelineVersion` records.
  • Visual Block Wiring & Live Code Preview — Add blocks from the palette, configure hyperparameters in the inspector, and inspect the generated Python script (`pipeline = loader >> cleaner >> trainer >> evaluator`).
  • Dry-Run Validation (/api/pipeline/validate) — Verify block compatibility and parameter schemas before saving.
  • Version Control (/pipeline_versions/<name>) — Every save creates an immutable PipelineVersion snapshot. You can compare versions and restore any prior configuration with one click.

4. Data Explorer: DuckDB, ConnectorX & RAWGraphs

ProjectCompass provides a dual-engine SQL workbench at /query_results/:

Local CSV & SQLite Queries (DuckDB)

  1. Upload CSV/TSV files at Data Upload (/data_upload/) or drop .csv / .sqlite files into Saved_data/.
  2. In SQL Runner (/query_results/), leave the connection selector on Local (DuckDB) and reference any file by its filename without extension:
-- Automatically rewritten by DataUtils.sql() to read_csv_auto('.../Saved_data/orders.csv') AS orders
SELECT
    region,
    COUNT(*) AS total_orders,
    ROUND(AVG(order_amount), 2) AS avg_order_value
FROM orders
WHERE status = 'COMPLETED'
GROUP BY region
ORDER BY total_orders DESC;

Remote Database Connections (ConnectorX)

  1. Navigate to Database Connections (/connections) and click New Connection (or declare preset connections in projectcompass.yaml).
  2. Supported dialects: postgresql, mysql, mariadb, mssql, oracle, clickhouse, and sqlite.
  3. Click Test Connection to verify connectivity and latency, then select the connection inside the SQL Runner or pass "connection": "warehouse_ro" to POST /api/query.
🛡️ Helm Control — Read-Only Enforcement & Encrypted Vault

All remote credentials are encrypted at rest via CredentialVault (Fernet AES-128-CBC + HMAC-SHA256 using DB_CONNECTIONS_KEY). Remote queries are strictly read-only (SELECT / WITH / EXPLAIN) and capped at DB_CONNECTIONS_MAX_ROWS (default 100,000 rows).

Visualizing Results with RAWGraphs

From any query result in /query_results/:

  • Click Save as Temporary Table (/tmp_table/) to materialize the SQL result as a new CSV in Saved_data/.
  • Click Open in RAWGraphs (/graph_analysis/) to inject the result dataset directly into the embedded RAWGraphs charting canvas.

5. AI Data Assistant & Per-Analysis Hybrid RAG

ProjectCompass features two complementary AI modes powered by Mithril:

Mode A: Sandboxed Dataset Q&A (/chat)

Select any dataset from Saved_data/ and ask a question in plain English (e.g., "What is the 90th percentile of revenue by product category?"). The agent generates a pandas expression, validates the AST to ensure zero unsafe calls, executes it against the DataFrame, and returns both the natural-language answer and the exact pandas snippet.

Mode B: Per-Analysis Hybrid RAG (/chat/<analysis_name>)

Every analysis in the catalog has its own dedicated knowledge base:

  1. Click Build RAG Index on an analysis card (or call POST /rag/index/<name>).
  2. utils/chunker.py splits Python AST nodes, SQL statements, YAML keys, Markdown sections, and user comments into semantic chunks.
  3. RAGStore embeds the chunks into a per-analysis ChromaDB collection (rag_data/) and pairs vector similarity with BM25 keyword scoring and Mithril cross-encoder reranking.
  4. Open /chat/<analysis_name> to ask deep architectural or analytical questions with cited source files and line numbers.

6. Schedules, Execution History & Webhooks

  • Execution Console (/executions/) — Inspect every historical run across structured analyses, pipelines, and k0s flows, complete with status badges (running, completed, failed), duration, and live SSE log streaming.
  • Cron Scheduler (/schedules/) — Attach standard 5-field cron expressions (e.g., 0 6 * * 1-5) to either local analyses or Kubernetes flows/chains, and configure optional webhook_url notifications.
