Web Routes, REST API & External CLI Reference

Complete endpoint catalog across all 8 Flask blueprints, authentication modes (Session, HTTP Basic, Bearer Token), JSON content negotiation, SSE streaming, and the standalone scripts/compass_cli.py command reference.

09 • Sextant & Telegraph REST JSON + SSE scripts/compass_cli.py

1. Authentication Modes & JSON Content Negotiation

ProjectCompass supports three authentication mechanisms evaluated by blueprints/auth.py:

  1. Browser Session Cookie — Established via POST /login/ after verifying credentials against SQLite `User` records or `ADMIN_USERNAME` / `ADMIN_PASSWORD_HASH`.
  2. Bearer Token Authentication (Recommended for CLI & Worker SDK) — Pass Authorization: Bearer <token> matching either a user's `api_token` in SQLite (`POST /api/tokens`) or the static `API_AUTH_TOKEN` environment variable.
  3. HTTP Basic Authentication — Pass Authorization: Basic base64(username:password).
🧭 Captain's Log — Dual HTML / JSON Endpoints

Operational routes such as /workers, /flows, /chains, /runs, and /schedules/ render HTMX/Jinja2 HTML when visited in a browser, and automatically return structured JSON when the client sends Accept: application/json or Content-Type: application/json.

2. Kubernetes Console & Orchestration Endpoints (k8s_bp)

Method Endpoint Description & Payload / Response
GET /workers Syncs Kubernetes nodes with SQLite (`k8s_workers`) and returns worker list (`Ready`, `NotReady`, `Removed`), CPU/memory capacity, and cluster availability.
POST /workers/register Pre-registers or updates a worker node record (`{"name": "worker-01", "role": "worker", "labels": {...}}`).
POST /workers/join-token Generates a signed k0s join token (`{"role": "worker", "expiry": "24h"}`) and returns the ready-to-run join command.
POST /workers/<name>/drain Cordons the node (`unschedulable=True`) and evicts non-DaemonSet pods.
DELETE /workers/<name> Deletes the node from Kubernetes (if reachable) and marks it `Removed` in SQLite.
GET /flows Lists all reusable Python Flows stored under `Analyses/` (`is_flow=True`).
GET /flows/<name> Returns flow metadata, `flow.py` source code, default `parameters`, `pip_requirements`, `secret_refs`, `image`, and version history.
POST /flows/save Creates or updates a Flow (`name`, `code`, `description`, `parameters`, `pip_requirements`, `secret_refs`, `image`, `cpu_request`, `memory_limit`, `node_selector`).
POST /flows/<name>/run Dispatches an isolated `batch/v1` Kubernetes Job (`pc-flow-job-<run_id>`). Accepts `{"parameters": {...}, "secrets": {...}, "wait": false}` and returns `{"run_id": 42, "status": "running", "job_name": "..."}`.
GET /chains Lists all linear Flow Chains (`FlowChain`).
POST /chains/save Creates or updates a sequential Flow Chain (`{"name": "daily-ml", "flow_names": ["ingest", "train", "score"]}`).
POST /chains/<name>/run Starts sequential execution of all flows in the chain (`{"parameters": {...}, "wait": false}`).
GET /runs Lists recent `ExecutionRun` records (supports `?flow_name=&limit=25`).
GET /runs/<run_id> Returns run status, start/end timestamps, `k8s_job_name`, and persisted `log_text`.
GET /runs/<run_id>/stream Server-Sent Events (`text/event-stream`) endpoint streaming live Pod stdout/stderr lines until Job completion.
POST /runs/<run_id>/abort Deletes the active Kubernetes Job/Pod and marks the run `aborted`.

3. Programmatic JSON REST API (api_bp & rag_bp)

Method Endpoint Description
GET /health & /api/health Liveness probe returning {"status": "ok", "version": "0.1.0"}.
GET /api/analyses Paginated catalog list supporting ?q= (FTS5 search), ?product=, ?owner=, ?page=, ?per_page=.
GET /api/analyses/<name> Full metadata, inputs, versions, rating summary, and comments for one analysis.
POST /api/analyses/<name>/run Executes a Structured Analysis or Kubernetes Flow with `{"parameters": {...}, "wait": false}`.
GET /api/data & /api/data/<name>/preview Lists datasets in Saved_data/ and previews top $N$ rows (`?limit=10`).
POST /api/query Executes SQL via local DuckDB or a saved ConnectorX connection (`{"sql": "SELECT ...", "connection": "warehouse"}`).
GET /api/search?q=<term> SQLite FTS5 full-text search across analysis titles, descriptions, products, owners, and countries.
POST /api/tokens & DELETE /api/tokens/<id> Generates or revokes Bearer API tokens.
POST /rag/build/<name> & /rag/index/<name> Chunks and embeds an analysis folder + comments into ChromaDB (`rag_data/`).
GET /rag/status/<name> & DELETE /rag/index/<name> Inspects or deletes the per-analysis ChromaDB RAG collection.
POST /chat/analysis/rag & /chat/analysis/rag/stream Answers questions over an analysis using hybrid Vector + BM25 search, Mithril reranking, and source citations.

4. Schedules, Catalog & Data Explorer Web Routes

Method Route Description
GET /schedules/ Lists all cron and interval schedules (`Schedule` model) across analyses, flows, and chains.
POST /schedules/create Creates a new cron or interval schedule (`flow_name`, `chain_name`, `analysis_name`, `cron_expr`, `parameters`, `webhook_url`).
POST /schedules/<job_id>/toggle & /schedules/<job_id>/delete Pauses/resumes or deletes a scheduled job in APScheduler and SQLite.
GET /, /overview, /analysis, /executions Main dashboard, platform overview, catalog browser, and execution history console.
GET / POST /pipeline_builder, /pipeline_versions/<name> Visual scomp-link ML pipeline designer and version history manager.
GET / POST /query_runner/, /query_results/, /graph_analysis/ DuckDB + ConnectorX SQL editor, result table pagination, and RAWGraphs visualization bridge.
GET / POST /connections/, /connections/new, /connections/save, /connections/<id>/test Encrypted remote database connection management and live latency testing.

5. External CLI Reference (scripts/compass_cli.py)

The standalone CLI in scripts/compass_cli.py (powered by BaseCompassCliClient and CompassCliRunner in utils/cli_utils.py) lets you operate workers, flows, chains, runs, and schedules from any terminal or CI/CD runner.

Environment Variables & Global Flags

export COMPASS_URL="http://localhost:8080"
export COMPASS_TOKEN="your-bearer-api-token"
# Or use HTTP Basic Auth:
# export COMPASS_USER="admin"
# export COMPASS_PASSWORD="your-password"

Complete CLI Command Cookbook

# 1. Inspect k0s worker nodes and cluster health
uv run python scripts/compass_cli.py workers list

# 2. Push (create or update) a Python Flow from a local .py file
uv run python scripts/compass_cli.py flows push churn-scoring ./flow.py \
  --description "Daily k0s customer churn scoring" \
  --params '{"region": "EMEA", "score_threshold": 0.7}' \
  --pip "compass-worker-kit>=0.1.0,scomp-link>=2.2.0" \
  --secret-refs "compass-master-auth" \
  --image "python:3.11-slim" \
  --message "v1.2 threshold tuning"

# 3. Trigger a Flow as an isolated k0s batch/v1 Job and wait for completion
uv run python scripts/compass_cli.py flows run churn-scoring \
  --params '{"region": "APAC"}' \
  --wait

# 4. List runs, inspect run status, or stream live Pod logs over SSE
uv run python scripts/compass_cli.py runs list --flow churn-scoring --limit 10
uv run python scripts/compass_cli.py runs get 42
uv run python scripts/compass_cli.py runs logs 42 --follow
uv run python scripts/compass_cli.py runs abort 42

# 5. Create and execute a sequential Flow Chain (StepA -> StepB -> StepC)
uv run python scripts/compass_cli.py chains save nightly-ml-chain "ingest-data,train-model,churn-scoring" \
  --description "End-to-end nightly pipeline"
uv run python scripts/compass_cli.py chains run nightly-ml-chain --wait

# 6. Create and toggle Cron / Interval Schedules
uv run python scripts/compass_cli.py schedules create \
  --chain nightly-ml-chain \
  --type cron \
  --cron "0 2 * * *" \
  --params '{"env": "prod"}'
uv run python scripts/compass_cli.py schedules list
uv run python scripts/compass_cli.py schedules toggle sched_nightly_ml_chain
